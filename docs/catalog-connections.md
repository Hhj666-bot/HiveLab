# 同一执行端使用多个独立连接

一个清单程序可以对应多个连接。例如同一套 ZCode 程序可以同时配置“智谱 API”和“智谱 Coding Plan”。每张人物卡选择一个连接；登录方式、API Key、模型、权限、额度、登录状态和原生账号目录按连接编号保存。

## 操作

1. 在“设置与成员连接 → 连接与版本”找到已安装的程序，点击“新增独立连接”，填写便于区分的名称并选择登录方式。也可以在人物卡的“使用的连接”下方创建，创建后会自动选中，保存人物卡后生效。
2. 回到“连接与版本”，在新连接中完成官方登录或填写 API Key。新连接共用已有程序文件，账号和密钥需要分别配置。
3. 在各人物卡的“使用的连接”中选择相应连接。下拉选项同时显示连接名和登录方式。

Kimi、GLM 的 API 默认模型可以留空后保存密钥，再在工位输入框旁选择话题模型。详见 [API 话题模型说明](api-chat-models.md)。

例如：将“GLM API”人物卡绑定“智谱 API / GLM API Key（BigModel 中国区）”，将另一张卡绑定“智谱 Coding Plan / BigModel 中国区官方账号登录”。之后修改一个连接不会改变另一个连接。

多张人物卡也可以主动共用同一个连接。连接设置会列出使用它的人物卡，修改该连接会影响这些共用者。需要不同登录方式时先新增连接，再分别绑定。

## 删除连接

外接连接标题行直接显示“删除连接”。确认框会列出使用它的人物卡；确认后删除所选连接及其 API 密钥，保留人物卡、历史对话、官方登录目录和已下载程序。关联卡片显示“未连接”，仍可编辑人物资料；在人物卡中选择其他连接并保存后，新话题使用新连接。旧话题保留原连接和模型，仅供查看、导出。

正在进行或排队的任务、未结束的项目流程、登录或版本操作会阻止删除，并在确认框中显示原因。取消确认不修改连接或密钥。其他独立连接不受影响。内置执行端继续沿用原有删除规则。

## 旧资料与会话

- 原有连接编号、账号目录、已保存密钥、人物卡绑定和聊天记录继续保留，不自动拆分或猜测每张卡要使用的账号。
- 人物卡改用另一个连接后，新话题使用新连接。原有话题保持原连接及模型，避免把旧账号的原生会话交给新账号续接；要使用新连接，请新建话题。
- 在同一个 ZCode 连接内更换登录方式时，仅清除该连接的原生会话绑定；工作台聊天记录和其他连接的会话保留。
- 各连接可以独立选择已安装版本；程序文件共用。只要还有一个连接使用某版本，就不能删除该版本。
- API Key 由 Electron safeStorage 加密，存放在 `secrets/<executorId>.secret`；官方登录目录是 `native/acp/<executorId>`。密钥值不进入数据库或界面快照。

## 实现与验证

清单编号 `catalogId` 只标识程序种类，独立连接使用不同的 `AcpExecutor.id`。`catalog.credentials`、版本查询、安装及切换通过 `executorId` 指定连接。旧调用未提供编号时优先沿用原始连接；原始连接已删除时使用该清单的现有连接。新增入口为 `catalog.connection.create`，不复制来源连接的密钥、登录资料、模型或环境变量。

回归测试见 `tests/catalog-connections.test.ts` 和 `tests/catalog-connections-electron-smoke.mjs`。桌面测试覆盖从人物卡和连接设置创建、分别绑定、API 与订阅共存、密钥加密、清除不影响另一连接、保存设置后模型保留及重启持久化。测试使用隔离资料、虚构密钥和本地不可用代理，不使用真实账号或发送模型请求；已加入 `npm run verify`。
