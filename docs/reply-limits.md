# 本次发言次数与终止

在茶歇室发送区点击“每人 1 次”设置下一条消息的正式回复次数。闲聊和开会分别记住最近一次选择。可以统一设置，也可以给各成员单独设置 0–100 次或不限；0 次表示本条消息不安排该成员发言。

每条普通用户消息会建立新的次数记录。设置按发送时的选择固定；发送之后修改面板只影响下一条消息。在场成员旁显示本条消息已安排的次数和上限。

一次正式回复机会计一次，包含只发表情、选择不发言或失败的尝试；同一回复的格式补正和连接重试不额外获得发言机会。举手投票和用户单独请求的会议纪要不占正式回复次数；已没有剩余正式回复机会的成员也不会被邀请举手。

开会按在场顺序轮流发言。未开启举手时，仍有剩余次数的成员可以继续下一轮；开启举手时仍沿用点名补充流程，次数是上限，并不要求用满。次数耗尽后等待新的用户消息；“继续讨论”不会重新补满本条消息的次数。

发送区的“终止发言”按钮始终可见。有本轮讨论或正在执行时可以点击，停止本房间当前发言，并撤回尚未开始的后续发言。终止过程中会显示“终止中”，暂时不能发送或继续讨论。其他工位、其他房间的任务不受影响；已完成的聊天内容保留。以后可通过新的消息重新开始，或明确继续尚有剩余次数的讨论。

实现采用后端逐成员计数和调度前检查，提示词中的次数仅用于说明，不能由成员输出的点名、问题或接话请求绕过。终止请求按房间合并，重复点击不会重复停止同一个运行。

测试包括：统一/分别次数、0 次、不限、次数重置、用户插话与旧回复隔离、会议顺序、达到次数后不再举手、格式补正计数、正在发言及排队时终止、重复终止、其他工位继续运行，以及界面参数、持久化、窄窗口和真实 Electron 的控件加载。测试均使用隔离数据，不发送模型请求。
