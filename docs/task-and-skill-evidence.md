# 任务详情、交接和技能证据

2026-10-29。对应《HiveLab-综合优化清单》AR-03、AR-04、AR-05，保留已有 AR-01 / AR-02 与 P0 行为。

## 任务详情（AR-03）

`projectFlow.get` 的任务和 `projectFlow.detail(kind: task)` 返回派生的 `context`，由 `project-task-context.ts` 读取持久记录组装。任务详情固定显示当前负责人、阶段、阻塞、最近活动、提交成果、复核版本、验收和下一步。运行分页不会丢失这些信息。

执行回执分别显示排队、投递、原生回合确认；成果提交、复核和验收另外展示。决定引用已有 Decision，展示适用任务/轮次、依据版本、用户选择与会话中的原始记录。历史决定和历史复核显式标记；尚未确认的方案草稿不作为已生效替代版本。已送达补充保持送达语义，只有已有业务记录进入 submitted / applied 时才相应更新。

一次流程快照内共享读取缓存，避免每项任务反复解码整份方案和历史记录。

## 交接与恢复（AR-04）

- 建运行和 outbox 沿用已有事务；确认方案、追加任务、任务改派的业务提交同时保存对应请求回执。
- 同一请求的回复丢失后重放持久回执；业务状态已改变但操作未完整结束时，保留待核对记录，不删除后自动重发。
- 恢复和接纳运行结果核对 operation、项目、会话、会话版本、执行端、当前负责人及已捕获的原生历史 ID。旧负责人或旧会话结果保留为历史，不接管新任务。
- 改派保存 handovers，保留原成员、原会话/运行、既有提交、要求版本、原因与来源决定；新负责人从现有记录取得交接上下文。当前工作副本仍遵循既有基线准备流程。
- 完整结果已落盘的运行可走既有只读核对与结果恢复；投递未知不会触发自动模型重发。完成提交与等待复核的状态继续一起落盘。

测试包含提交前事务回滚、提交后回执重放、投递前/投递后未确认/确认后结果落盘的启动恢复、旧运行归属拒绝、改派请求幂等。

## 技能来源与运行证据（AR-05）

技能详情展示来源、独立环境、管理者、声明版本（若有）、SHA-256 和最近检测时间。导入技能另存原路径、导入时间与内容摘要；同名 common / codex 等副本保持独立。

发送时冻结正文、摘要和来源快照。排队后磁盘改动不改变本轮输入。运行诊断分别列出用户选择、工作台附加正文、原生目录发现、按需 read_skill 成功读取，以及原生自动加载。原生未提供逐技能加载凭据时保持“未确认”；Hook 配置和调用记录单列，不能从“已安装”推断 Hook 已执行。

通用技能和 Codex 个人技能可对同名副本进行更新预览。包摘要包含支持文件；存在本地修改或缺少导入基线时显示原因并保留原副本。未修改副本的更新会归档旧包，保留启停状态。旧安装没有凭空补造导入基线。技能索引与按需读取能力继续保留。

新增界面使用 CSS Modules，沿用现有暖色、字体与间距令牌，不改写保存的外观参数。
