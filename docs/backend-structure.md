## 模块职责

| 模块 | 职责 |
| --- | --- |
| `engine.ts` | 组装协作者，保留房间上下文、维护状态、项目删除和流程归属限制，以及运行队列、会话生命周期 |
| `api/{rooms,members,work,automation,data}.ts` | 按业务域登记请求处理函数；参数使用 `Record<string, unknown>`，既有校验与业务操作保留 |
| `api/registry.ts` | 从实际处理函数推导 `RpcMethod` 联合类型，使用 `Map<RpcMethod, RpcHandler>` 精确分发，未知请求保持原错误 |
| `provider-registry.ts` | 探测、兼容报告、登录失效、额度/余额、查询去重、版本戳、探测重试及定时器清理 |
| `agent-tools.ts` | 会话工具目录、控制接口、插件审批、文件访问、生成成果与电脑授权状态 |
| `automation-speaker.ts` | 定时单次发言、每日开场、成员闲聊、房间占用与结果结算 |
| `flow-commands/` | 按方案、轮次、任务、补充、决策、恢复、生命周期和记录拆分原 `mutate()`；补充任务的完整执行逻辑也迁入此处 |
| `pump.ts` | 合并重复唤醒，同一控制器的扫描不并行；执行中或清理前到达的唤醒不会丢失；关闭等待当前扫描 |

协作者通过显式 Host 接口取得所需状态和操作。会变化的设置、房间上下文、提供方快照使用 getter；函数回调绑定其实际所属对象。

## 保持的边界

- RPC 的传输白名单仍在 `shared/rpc-methods.ts`；注册表不会绕过主进程来源校验或引擎维护限制。
- `ProjectFlowController.invoke` 继续负责请求编号、重复请求共享、保存回执、失败处理和完成后的唤醒；资源模块只处理具体变更。
- 方案捕获基线前后的版本检查、项目路径范围、事务写入、补充来源和未知投递处理均保留。
- 账号查询仍按配置与账号版本戳丢弃过时结果，失败不自动重发成员任务。
- 调度泵只重做已有新唤醒要求的队列扫描，不重放任务；关闭后不接受新扫描。
- 数据库格式、主进程权限、渲染样式和依赖清单沿用现有实现。

## 对报告的核验与范围

报告描述的三处“单飞泵”，当前代码实际是项目流程和联合评审两处异步泵，加圆桌 `sync()` 的同步重入保护。因此仅统一前两处，保留圆桌即时同步语义。

报告称自动发言是单一长方法，当前已存在 `speakAutomatically`、`lifeSpeech`、`automaticSpeech`；本轮将它们及房间占用辅助方法整体迁入协作者。

三类成员回复的恢复、补正、证据及调用计数规则有实际差异，继续由各业务域维护。本轮范围是职责提取、请求分发和两处异步调度泵的共用。
