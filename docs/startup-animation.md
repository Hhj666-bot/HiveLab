# 启动动效

入口：**设置与成员连接 → 外观 → 启动动画**。内置动画只有一个“隧道展开”：HiveLab 标志是一个开关，按下去打开一个新世界。不需要视频，也不需要为它上传素材。流程如下：

1. **按下**：全屏纯色平面（白天白底、夜间黑底，跟随应用主题），中央是较小的 HiveLab 标志，与平面同色，只由一圈细线勾出外形。按下时该形状向内凹陷，随后停顿约 0.25 秒。
2. **隧道展开**：按钮表面先化开透出壁纸，标志图形继续向深处缩小远去，最后才消失，按钮变成一扇小窗。小窗在约 3 秒内缓缓铺满屏幕，一圈圈同形状的细线从窗口边缘向外退去，形成隧道壁；窗内的壁纸同时从 72% 的远处推近到原大，定格帧和实时壁纸都一样。按下会等工作室就绪、主线程安静下来（最多等约 2.8 秒），保证展开起步流畅。由 WebGL 绘制，不支持时退回较简单的 Canvas 版。
3. **入场**：壁纸先单独完整显示约 0.5 秒，然后侧栏从左、顶栏从上、立绘和底栏从下、右下角气泡从右滑入，用时约 2 秒，起步轻柔。全程只改位置，不改透明度。

每次打开时侧栏都是折叠状态（只显示图标），由启动脚本在 React 之前写入，所以不会先展开再收起。手动展开只在本次运行有效，展开宽度会保留；隐藏状态的侧栏保持隐藏。

入场不属于动画开关：关闭启动动画只会把动画换成简洁加载画面，入场照常。开启“跟随系统减少动态效果”且系统要求减少动态时，三段都不播放。按 Esc 可跳过动画。

## 自适应文字

界面入场前颜色就已定好，滑入全程不再变化。壁纸单独显示时，界面就在最终位置，只是透明，所以测量到的就是最终位置；入场开始的那一帧才移到屏幕外。用过的壁纸直接取缓存；新壁纸在它单独显示时截图，把各层界面的底色叠上去估算，最多等 1.4 秒。入场期间不做任何判断。界面到位后再做一次真实取样，只有估算确实不对时才按原有的停留和保持时间调整。

## 入场不能用 CSS 过渡

早先入场用 CSS 过渡。正常启动时，屏幕上看不到中间过程，界面在接近终点时一帧冒出来，单帧跳变占全程 74%～86%；挂着调试连接启动时却完全正常（4%），所以 Playwright 和 CDP 截帧都测不出来。现在由主线程逐帧驱动，和隧道一样，帧时间有上限，卡顿后从原处继续，不会跳到后面。

入场途中立绘也不能再解码。立绘只上屏一次（处理完才显示，不再先显示原图再替换），入场前等全部图片解码完成，最多约 2.5 秒。

早先界面在壁纸单独显示时待在屏幕外，测量颜色时临时取消位移，真实屏幕上偶尔会闪现一帧界面，现在已改为透明待命。

验证这类问题必须录真实屏幕（用桌面复制接口，比如 ffmpeg 的 `ddagrab`；`gdigrab` 会抓到整层缺失的假象），并且不挂调试连接启动。CDP 截帧和 `getBoundingClientRect` 读数都不能证明用户看到了动画。

## 液态玻璃

入场由 `startup-boot.ts` 逐帧写入 `--enter-*` 变量，再由 CSS `translate` 取用，不动 `opacity`、`filter`，所以玻璃在移动中持续取样身后的壁纸。壁纸是最底层，入场时不移动也不改变大小，分层规则见 `docs/ui-layers.md`。这些属性会让元素的 `backdrop-filter` 取不到壁纸，修改 `public/startup/boot.css` 里 `startup-stage`、`startup-entering` 的规则时不要加入。

启动遮罩本身不是玻璃。它写着 `role="dialog"`，而液态玻璃会匹配所有对话框，所以 `liquid-glass.tsx` 的 `ownsGlass` 排除了它，`boot.css` 也清掉了它的 `backdrop-filter`。否则动态壁纸要透过一块全屏玻璃才能看到：整体偏移约一百多像素，开场中途某一帧才跳回正位。静态壁纸被定格帧盖住，看不出这个问题。

## 随壁纸自动生成的启动场景

隧道展开使用的背景由程序自己识别：`src/renderer/startup-scene.tsx` 的 `StartupSceneSync` 监听 HiveLab 首页当前使用的背景。每次上传或更换背景（不论从设置、Wallpaper Engine 导入还是背景弹窗）都会立即生成新场景，写入 `localStorage` 的 `hivelab.startup-scene`。启动脚本在 React 和后端之前就能读到它，所以小窗打开时看到的就是用户的壁纸，不必等工作室加载完。

| 壁纸类型 | 生成内容 |
| --- | --- |
| 静态图片 | 原图缩到最宽 2560 的 WebP 帧 |
| 内置工作室 | 不生成文件，记录四个时段的图片地址 |
| 纯色 | 不生成文件 |
| 视频、场景、网页壁纸、GIF | 不生成帧，窗口直接透出正在播放的真实壁纸 |

动态壁纸不用定格帧，否则窗口里是静止画面，开场结束时才突然动起来。代价是标志要等壁纸开始播放后才按下，壁纸最多等约 3 秒。遮罩、模糊和适配方式不写进帧，由启动脚本按当前窗口实时应用，改这些设置不用重新生成。帧保存在 `startup-media/backgrounds`，始终只留当前一张（`BackgroundLibrary.saveFrame`）。

隧道的窗口是画布上的透明洞，洞下面是场景帧，没有场景时就是真实壁纸。两种情况走同一份绘制代码，所以生成失败、还没生成或帧文件丢失都不会出错，只是按钮要等到工作室和壁纸就绪后才按下。旧壁纸的帧在换壁纸时立即作废，不会用过期画面开场。

## 就绪与失败

React 的首个有效快照提交后，由 `App.tsx` 等待两次绘制回调再报告就绪；启动脚本还会等壁纸画完（最多 3 秒）。有场景时最多等约 2.8 秒就会打开，打开后停在壁纸帧上，就绪后再入场。超过 1.5 秒未就绪才显示状态文字和跳过按钮。后端或界面渲染失败时立即解除遮罩，不播放入场，直接显示原有错误与恢复操作。加载超过 60 秒显示重新加载按钮。预览不重启应用，也不影响后台任务。

## 自定义视频

可上传本地视频代替内置动画，视频结束后先显示壁纸再入场；设置了主页交接截图时，按“视频末帧 → 截图 → 真实主页”淡入，不播放入场。自定义视频不可用时退回隧道展开。播放方式、声音和音量只在使用自定义视频时显示。
