# HiveLab 设计优化指导

更新日期：2026-10-28  
适用项目：`D:\HiveLab\source`  
用途：指导后续界面优化；已落实的内容见第 5 节，其余待办不代表已经修改或部署。

## 1. 设计判断

HiveLab 应保留角色、壁纸、暖色调和彩色玻璃这些个人特色。优先改善阅读层次：让正文容易读，让操作容易找，让新打开的面板获得焦点，同时保留背景页面的可读性。

当前主要问题是多个区域同时吸引注意力：复杂壁纸、彩色气泡、工具栏、描边和操作条相互叠加。单纯增加模糊、降低透明度或加强发光，不能稳定解决这些问题。优化应从表面职责、文字层级、操作权重入手。

### 参考的使用方式

依据为本地 [Apple 风格分析文稿](D:/Vibe-coding/awesome-design-md-main/design-md/apple/DESIGN.md)。该文稿是第三方对 Apple 网站的设计分析，版本标记为 alpha，并非 Apple 官方桌面应用规范。

| 参考中值得采用的原则 | HiveLab 中的落实方式 |
| --- | --- |
| 内容优先、界面退后 | 正文保持稳定阅读体验，导航和工具按钮降低装饰权重 |
| 少量且一致的强调色 | 沿用 HiveLab 暖色品牌；区分操作色、角色身份色和状态色 |
| 明确的字体与间距层级 | 在已有字号、圆角和间距基础上归一，不引入第二套体系 |
| 克制的描边与阴影 | 普通阅读区域安静，浮层承担必要的层次表达 |
| 清晰的主次操作 | 一个场景突出一个主要动作，其他动作保持可见和易用 |
| 按组件逐步迭代 | 每批只处理一类问题，保留现有偏好与业务行为 |

网站的大标题、大留白、Apple 蓝色和拉丁字体字距不直接套用。HiveLab 是需要长时间阅读、处理文件和管理会话的桌面工作区，应延续现有中文字体栈与紧凑布局。

## 2. 已有基础与需要保留的约束

值得保留的基础：角色辨识度高；聊天、文件与终端组合完整；已有主题变量、约 880px 的阅读宽度约束，以及减少动态效果、减少透明效果等适配。

后续修改必须遵守：

- 保留壁纸、角色形象、成员颜色和用户选择的气泡底色。
- 沿用现有透明度控件，不增加重复滑条。透明度仍为 **0% 不透明，100% 完全透明**。
- 不覆盖用户保存的透明度、颜色、页面范围或全局同步设置。
- 不通过隐藏最低不透明度改变滑条含义。用户主动选择高透明度时，允许相应视觉结果。
- 顶栏和侧栏使用同一套基础材质；参数相同时应连贯，避免额外渐变、阴影或折射造成接缝。
- 保留消息滚动到顶部玻璃栏背后的布局。
- 保留回复操作条的可见性，不能为了简洁改成仅悬停显示。
- 视觉优化以 renderer 和样式为主，不顺带改变模型调用、权限、文件操作或消息存储。

## 3. 表面与聚焦规则

统一材质不意味着所有区域都采用相同遮罩。基础参数保持一致，再根据区域职责使用明确、有限的附加效果。

| 区域 | 目标效果与参数来源 | 避免的问题 |
| --- | --- | --- |
| 顶栏、侧栏 | 共用导航底色、滤镜；沿用原有透明度设置 | 相同设置下出现不同色温、雾度或接缝 |
| 回复、我的消息、输入框 | 沿用各自选色和透明度，保留淡淡彩色玻璃感 | 自定义底色被玻璃样式覆盖 |
| 普通菜单与选择器 | 共用液态玻璃参数与独立的“菜单透明度”，与顶栏分开保存 | 每个菜单各自写一组背景和模糊 |
| 话题管理 | 同样属于菜单，使用统一菜单透明度，保留略深底色 | 底下消息与面板文字互相干扰 |
| 话题管理打开后的其他区域 | 轻度压暗、不额外模糊，仍可阅读 | 全屏模糊导致无法参考原会话 |
| 需要完成或取消的对话框 | 使用明确遮罩和适度模糊，集中处理当前动作 | 与普通辅助面板没有区别 |

### 本轮已实现的聚焦效果

话题管理打开时，其他区域增加 **12% 黑色遮罩**，不额外模糊；话题面板保持自身亮度。该视觉遮罩不拦截鼠标，不把话题管理变成阻断其他阅读操作的模态窗口。

源码已构建并部署到日常版，视觉效果由用户继续体验。关闭面板后的遮罩清理、缩放及尺寸变化等，仍列入下方人工验收清单。

当前玻璃对话框使用 24% 深色遮罩和 5px 背景模糊，可作为阻断式弹窗的现有基线。上述数值用于区分辅助面板与对话框，不新增成另一组外观滑条。

## 4. 优化任务与优先级

### P0-01：优先保证壁纸上的文字阅读

**问题：** 亮暗变化大的壁纸与透明表面叠加后，正文、说明和背景细节容易混在一起。

**执行：**

1. 检查正文、元信息、辅助说明是否分别使用合适的文字层级，避免同一条消息内无意混用多种亮度。
2. 优先修正遗漏的底色、重复透明层和错误继承，确保现有颜色与透明度确实作用到对应区域。
3. 保留既有自适应文字能力；避免通过更频繁的明暗切换制造阅读跳动。
4. 默认样式需要调整时，先提供预览并明确影响；不自动改写已有用户设置。

**修改位置：** `src/renderer/team.css`、`src/renderer/chat-appearance.css`、`src/renderer/liquid-glass.css`、`src/renderer/adaptive-text-groups.ts`。

**验收：** 常用透明度下正文与操作可辨认；回复、我的消息和输入框选色立即生效；文字与按钮本身不随底色透明度一起变淡。

### P0-02：完成话题管理的阅读与聚焦层次

**问题：** 话题管理曾与下方消息重叠，面板内文字和按钮缺少清楚的视觉边界。

**执行：** 保留本轮略深底色和轻度外部压暗；先由用户体验，再根据明确反馈微调。面板内标题、话题名称、操作和说明按重要性排列；不要继续增加全屏模糊。

**修改位置：** `src/renderer/topics.tsx`、`src/renderer/topic-focus.tsx`、`src/renderer/topic-focus.css`、`src/renderer/liquid-glass.css`。

**验收：** 打开后视线自然落到话题管理；原会话仍可读；遮罩随面板位置变化；关闭后无暗层残留；新开的确认对话框仍在正确层级。

**状态：** 底色、聚焦层与话题信息分组均已实现，视觉效果待用户验收。

### P0-03：收拢材质参数来源

**问题：** 局部背景、阴影和透明度的重复定义，会让“设置相同”与“看起来相同”脱节。

**执行：**

1. 以统一玻璃参数和 `--glass-menu-opacity` 为菜单参数来源，检查后续新增菜单是否接入；顶栏继续使用 `--workspace-header-opacity`。
2. 保留气泡、输入框、文件预览和终端各自已有的设置范围，不把它们强行并入顶栏透明度。
3. 话题管理的略深底色保留为明确例外，避免其他菜单无意继承该附加暗层。
4. 按实际修改的组件清理硬编码，不进行一次性全项目样式重写。

**修改位置：** `src/renderer/sidebar-layout.css`、`src/renderer/file-preview-panel.tsx`、`src/renderer/liquid-glass.css`、`src/renderer/liquid-glass.tsx`。

**验收：** 顶栏与侧栏同设置时材质一致；菜单透明度同步影响下拉、弹出菜单、话题管理及设置窗口，调整菜单不改变顶栏；外观设置中没有重复控件。

### P1-01：统一正文和辅助文字的字号

**问题：** 全局 Markdown 正文使用 `--fs-body`（15px），聊天气泡存在 `--fs-base`（14px）的覆盖，长回复阅读体验不一致。

**执行：**

- 正文以现有 15px 变量为统一起点，优先去除不必要的 14px 覆盖；实际大小由预览体验决定。
- 中文正文延续约 1.65–1.75 的行高，保留段落和列表间距。
- 工具文字以现有 13–14px 层级为主；时间、计数等使用次级样式，不靠极小字号降低权重。
- 保留现有中文字体栈、代码等宽字体和约 880px 阅读宽度，不套用网站展示标题尺寸或负字距。

**修改位置：** `src/renderer/styles.css`、`src/renderer/team.css`。

**验收：** 长回复正文、列表和代码块层级清楚；调整字号后按钮、气泡和输入区无裁切；Windows 常用缩放下仍可读。

### P1-02：建立稳定的操作主次

**问题：** 部分工具条中多个按钮使用接近的背景、边框和亮度，主操作不够突出。

**执行：**

- 沿用暖色品牌作为统一操作强调，避免另加 Apple 蓝色体系。
- 主要操作突出，次要操作减弱填充或描边；删除等危险动作保留独立语义色。
- 成员颜色用于身份识别，在线、警告和失败颜色用于状态，避免互相替代。
- 回复操作条保持常显；通过降低整条底色和边框权重获得安静效果。

**修改位置：** `src/renderer/styles.css`、`src/renderer/team.css`、`src/renderer/topics.tsx` 及对应组件样式。

**验收：** 用户能迅速找到当前主要动作；复制、回复、导出等无需悬停寻找；危险操作容易区分。

### P1-03：统一圆角、边界与间距

**问题：** 多层描边、阴影和玻璃高光同时存在时，普通内容卡片与浮层的层级容易混淆。

**执行：** 以已有 8 / 12 / 16 / 22px 圆角层级归类组件；间距优先使用 4 / 8 / 12 / 16 / 24px。普通消息与内容块减少重复边界；菜单、弹窗等浮动区域保留必要的描边和阴影。已选中、键盘焦点和可拖动区域仍需明确可见。

**修改位置：** `src/renderer/styles.css`、`src/renderer/team.css`、`src/renderer/liquid-glass.css` 以及本批涉及的组件样式。

**验收：** 同类控件的高度、圆角和内边距一致；浮层与内容区可区分；键盘焦点不因减弱装饰而丢失。

### P1-04：整理话题管理与外观设置的信息结构

**话题管理：** 话题名称为首要信息；当前状态紧邻名称；消息数、时间和说明使用次级样式。整理摘要的成员选择形成独立控制组。改名、压缩、导出、清空和删除按用途分组，危险操作与常用动作拉开距离；先保留已有入口，避免为视觉简洁增加查找步骤。

**外观设置：** 常用项优先展示：主题、液态玻璃开关、页面背景、聊天底色与透明度。现有七项玻璃参数可折叠为“高级材质参数”，全部保留。透明度仍只在原有页面背景和聊天外观中调整，说明文字准确指向它们。

**修改位置：** `src/renderer/topics.tsx`、`src/renderer/appearance-settings.tsx`、`src/renderer/chat-appearance.tsx` 及对应样式。

**验收：** 无需理解折射术语即可完成常用外观设置；展开后仍能调整所有既有材质参数；话题信息和操作分组明确；保存范围与“应用到全部页面”的语义保持一致。

### P2-01：收敛动态效果，补齐状态表达

**执行：** 在核心阅读问题解决后，再处理动态细节。每次操作保留清楚的主要反馈，避免多个区域同时缩放、闪光。继续遵循减少动态效果的系统偏好。为加载、等待审批、失败和重试保留可读文本，不只依赖颜色或动画表达状态。

**修改位置：** `src/renderer/liquid-glass.tsx`、`src/renderer/liquid-glass.css` 及具体状态组件。

**验收：** 关闭动态效果后仍能理解当前状态；视觉整理不改变原有执行和权限流程。没有测量结果时，不以性能问题为理由重写动效系统。

## 5. 推荐执行顺序

| 批次 | 范围 | 交付结果 |
| --- | --- | --- |
| 第一批 | 用户体验本轮话题聚焦；修正明确的阅读和材质继承问题 | 话题管理可读、背景可参考，透明度含义一致 |
| 第二批 | 正文字号、文字层级、回复操作条权重 | 长回复阅读更稳定，常用操作保持易用 |
| 第三批 | 话题信息分组、外观设置顺序和高级参数折叠 | 常用任务更容易完成，参数入口完整 |
| 第四批 | 本批涉及组件的圆角、间距与动效收敛 | 形成一致细节，避免扩大成全界面重做 |
