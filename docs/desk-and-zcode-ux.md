# ZCode 与工位交互调整

## ZCode 权限与对话

受限权限下，已登录的 ZCode 可以按原生 `plan` 只读模式对话。以前工位默认请求写入，而 ZCode 的写入实现要求自动命令、任意文件范围及联网，普通“请求批准／帮我批准／自定义”权限因此会在发送前被拦截。

现在每轮会收窄到当前执行端能落实的只读模式，运行诊断也记录实际只读状态，人物卡和话题保存的权限意图保持不变。需要写入文件时，由用户在输入框旁选择“完全访问”，之后的新任务按原有 `yolo` 写入模式执行。

文件工作副本继续按用户的话题意图准备；只读执行后再授予写入权限，不会把工作项目改为直接写原目录。旧的失败记录保留，不自动重发。此次不改变账号登录资料或自动授予更大权限。

## 工位新话题

工位点击“开新话题”直接创建，不再先弹出命名窗口。暂时显示“新话题”，第一条用户消息写入后复用已有的自动命名逻辑，使用消息开头 20 个字符（合并空白并去除开头的有效 @ 提及）。话题和会话标题同步保存。

手动改名入口继续保留在话题管理中。手动名称不会被后续消息覆盖；旧话题继续保留，不重新命名。茶歇室原有归档／继承摘要流程保持原规则。

需要带上旧摘要时，可以在“话题操作 → 新话题选项”打开原有的可选命名／继承设置；“开新话题”主按钮保持直接创建。

## 主页人物资料卡

主页立绘左键进入工位，右键打开原有的人物资料卡；也支持键盘菜单键或 Shift+F10。资料卡与左侧成员列表共用同一实现。长按拖动站位继续保留。

## 连接编辑入口

连接标题栏移除无效感的“设置”按钮。需要编辑名称、环境变量或权限时，可使用连接内明确的“编辑连接信息”展开区；登录、模型和版本控件仍直接可用。

## 验证范围

回归覆盖 ZCode 受限权限只读执行、明确授权后的写入、工作副本边界、两个人物工位的自动命名及手动改名保留、真实 Electron 的直接创建与重启持久化，以及主页左／右键和资料卡。模型任务均使用隔离的模拟成员，未调用真实付费模型。

## 消息提醒

成员任务完成、需要回答或授权、运行失败或结果不确定，以及待处理中的验收、决策、登录失效等新增事项都会触发提醒。应用在前台时显示可点击的消息卡片；在后台、最小化或托盘中时使用 Windows 原生通知并闪烁任务栏。通知点击会唤起应用并定位到相应对话或待处理项目，不会替用户批准、验收或重新发送任务。

提醒集中显示在工作区顶部，多条提醒可切换查看。正在查看的对应对话会自动标记已读；切换到其他对话后，新提醒保留到点击或回到对应对话。编辑设置等弹窗打开时，提醒保留在弹窗下方，不覆盖表单及保存按钮。

首次启动和恢复资料不重播历史消息；同一审批和它对应的待处理项目合并提醒，也会捕获瞬间完成的任务和稍后才写入完成时间的任务。系统通知发送失败时回退到应用内卡片。沿用“工作台 → 外观与提醒 → 成员完成或需要你时通知我”开关，默认开启；不再依赖浏览器通知权限。

提醒测试覆盖完成、问题、审批、失败、去重、恢复、后台通知调用、脱敏以及点击后只导航。Electron 后台集成测试拦截原生通知的显示，避免测试消息进入系统通知中心；真实账号的任务和 Windows 实际横幅显示仍需要在日常使用中验收。
