# API 连接与话题模型选择

Kimi 和 GLM 的 API Key 可以单独保存，连接中的默认模型是可选项。留空时不会再报“请填写这个 API 账号可用的模型”。已有默认模型继续兼容。

## 操作

1. 在“连接与版本”选择相应地区、API 登录方式，填写密钥并保存。默认模型可以留空。
2. 进入成员工位，在输入框旁点击当前模型按钮，选择这个话题的模型并保存。从下一轮开始生效，其他话题的选择保持不变。
3. 模型不在清单中时，选择“其他模型（填写 API Model ID）”。手动输入时不会按每个字符触发连接探测。

连接默认、人物卡／项目默认、话题选择继续按现有继承关系解析；已开始的任务使用启动时冻结的配置。更换 API 登录地区或提供方后，原生账号仍按独立连接隔离。

## Kimi

应用只读请求当前所选 Kimi API 服务的 `GET /models`，显示真实 API Model ID。接口暂不可用时显示常用模型，并保留手动填写入口；模型清单和余额检查不发送模型任务。

Kimi Code CLI 的 `KIMI_MODEL_*` 临时入口会把实际模型映射到内部别名 `__kimi_env_model__`。每轮启动时，应用将该话题选择写入本轮的 `KIMI_MODEL_NAME`，通过原生别名选择和核对配置，并向界面返回实际 API Model ID。连接里的旧默认值不会覆盖本轮的话题选择。进程复用指纹也包含实际所选模型，切换时不会复用旧模型进程。

旧 Kimi 话题保存过内部别名时，界面会用连接当前报告的实际模型显示；原始运行记录保留。密钥仍只放在加密存储及进程环境中，不写入 Kimi 配置文件。

原生别名确认代表本轮环境配置被采用，不代表 API 服务在响应中报告了实际模型，因此运行配置证据保持 `accepted`。

## GLM

默认模型可留空。应用提供现有 GLM 模型选项；不指定默认值时沿用应用的 `glm-5.3-flash` 默认值。对话中明确选择的模型优先写入本轮 API 请求体，覆盖连接默认值；可以在同一个话题中连续切换模型。

## 验证与参考

回归包括密钥留空模型保存、Kimi 四种 Key 登录地区／通道、真实 API ID 模型清单、连续两轮模型切换、旧内部别名显示、自定义 API ID、连接隔离和删除保留资料。普通测试使用模拟成员或本地 HTTP 服务，不使用真实账号和付费模型。

- Kimi 官方模型清单接口：https://platform.kimi.com/docs/api/list-models
- Kimi 临时环境模型机制：https://moonshotai.github.io/kimi-code/en/configuration/env-vars.html
- 本机 Kimi Code CLI 2.1.1 离线实测：同一原生会话的两轮请求发往本地 HTTP 模拟服务，请求体分别使用两个不同的模型 ID。
